# Статическая приоритизация без переобучения

Приоритет задаётся номером дрона: дрон 0 самый старший, дрон N-1 самый младший. Сеть не меняется и не дообучается, меняется только то, каких соседей и как она видит.

## Переключатель

`--quads_static_priority`:

- `off` — без приоритета, исходное поведение (значение по умолчанию);
- `mask` — дрон видит только старших соседей (два ближайших среди дронов с меньшим номером), младших для него нет. Если старших меньше двух (у дрона 0 их нет), в пустой слот кладётся «никого рядом»: сосед на максимальной дистанции с нулевой относительной скоростью;
- `soft` — дрон видит двух ближайших соседей как обычно, но старшего соседа ему показывают ближе, чем он есть: относительная позиция умножается на `--quads_static_priority_scale` (по умолчанию 0.7).

Флаг работает в любой команде, которая создаёт среду, например при просмотре полёта:

```sh
python -m swarm_rl.enjoy --algo=APPO --env=quadrotor_multi --train_dir=... --experiment=... \
    --quads_mode=o_swap_goals --quads_static_priority=mask
```

## Сравнение режимов

`swarm_rl/eval_static_priority.py` прогоняет модель в нескольких режимах на одинаковых стартах, целях и препятствиях и считает долёты без столкновений, столкновения и время до цели, в том числе по группам номеров дронов.

С приоритетом и без:

```sh
python -m swarm_rl.eval_static_priority \
    --cfg config.json --checkpoint checkpoint_000781254_1000005120.pth \
    --num_agents 8 100 --episodes 10 --scenario o_swap_goals \
    --modes off mask --out results_swap
```

Только с приоритетом: `--modes mask`, только без: `--modes off`, все три: `--modes off mask soft`.

`--scenario` — название сценария (`quads_mode`), например `o_random`, `o_swap_goals` или новые коридор и тупик. Результаты сохраняются в папку `--out`: `summary.csv` (средние по режимам), `by_rank.csv` (по группам номеров, группа 1 — самые старшие), `episodes.csv` и `drones.csv`.

## Коридоры и тупики

`swarm_rl/run_layout_suite.py` принимает тот же переключатель: `--static_priority off|mask|soft` и `--static_priority_scale`. Каждый режим запускается в свою папку `--output`. Готовые эпизоды при повторном запуске не пересчитываются, поэтому запуск другого режима в папку с результатами прошлого режима останавливается с ошибкой.

```sh
python -m swarm_rl.run_layout_suite \
  --checkpoint experiments/swarm100-1b/checkpoints/checkpoint_000781254_1000005120.pth \
  --config experiments/swarm100-1b/config.json \
  --output results/suite_off --static_priority off \
  --agents 8 100 --episodes8 16 --episodes 8 --duration 15 --workers 2

python -m swarm_rl.run_layout_suite \
  --checkpoint experiments/swarm100-1b/checkpoints/checkpoint_000781254_1000005120.pth \
  --config experiments/swarm100-1b/config.json \
  --output results/suite_mask --static_priority mask \
  --agents 8 100 --episodes8 16 --episodes 8 --duration 15 --workers 2
```

Сравнение по схемам на одних и тех же сидах (старты, цели и стены совпадают):

```sh
python scripts/compare_static_priority.py --runs off=results/suite_off mask=results/suite_mask \
    --output results/priority_comparison.csv
```

Режим записывается в `manifest.json`, в `effective_config.json` каждого эпизода и в колонку `static_priority` файла `episodes.csv`. Анализ одной серии (`scripts/analyze_layout_suite.py`) запускается для каждой папки отдельно, как раньше.

## Тесты

```sh
export PYGLET_HEADLESS=true OMP_NUM_THREADS=1
python -m pytest tests/ -q
```

`tests/test_static_priority.py` проверяет, что `off` совпадает с исходным наблюдением, `mask` показывает только старших соседей, `soft` меняет только позиции старших, флаг доходит до среды в случайной среде, коридоре и тупике, а сравнение берёт только общие эпизоды.

## Статическое торможение `brake`

`run_layout_suite --static_priority brake` добавляет проверку между замороженной
политикой и шагом симулятора. В начале шага политика выдаёт обычные команды.
Каждый дрон публикует прогноз своего движения по текущей скорости. Щит
рассматривает все пары, включая дронов вне двух соседей, которые видны
актору. Обход идёт от меньшего номера к большему. Если прогноз младшего
сближается с уже принятой траекторией старшего, младшему подставляется цель
зависания в точке начала уступания. Политика пересчитывает его моторную
команду. Прогноз тормозящего дрона используется при проверке следующих дронов
в том же шаге, поэтому уступание распространяется по цепочке.

Решение принимается до `env.step`. Симулятор исполняет один набор команд за
шаг. Прогноз торможения предполагает линейное снижение скорости до нуля за
0,25 с. Это оценка по кинематике, и реальная траектория замороженной политики
может отличаться. Щит проверяет только расстояния между дронами. Сложность
проверки попарная по числу дронов при фиксированном числе сегментов прогноза.

По умолчанию горизонт прогноза 0,65 с, порог равен 1,8 порога столкновения
симулятора, цель зависания действует минимум 0,2 с. После 2 с непрерывного
ожидания один дрон на 0,5 с получает право проезда, затем возвращается
порядок по номерам. Настройки доступны через `--brake_horizon`,
`--brake_distance_scale`, `--brake_stopping_time`, `--brake_hold`,
`--brake_max_wait` и `--brake_release`.

### Полное сравнение на 18 схемах

```sh
export PYGLET_HEADLESS=true MPLBACKEND=Agg OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
config=experiments/swarm100-1b/config.json
checkpoint=experiments/swarm100-1b/checkpoints/checkpoint_000781254_1000005120.pth
python scripts/download_pretrained.py --output "$(dirname "$checkpoint")"

for mode in off mask brake; do
  python -m swarm_rl.run_layout_suite \
    --checkpoint "$checkpoint" --config "$config" --static_priority "$mode" \
    --agents 8 100 --episodes8 16 --episodes 24 --duration 15 --no_diagnostics \
    --output "results/static-brake/$mode"
done

python scripts/compare_static_priority.py \
  --runs off=results/static-brake/off mask=results/static-brake/mask brake=results/static-brake/brake \
  --output results/static-brake/comparison.csv
```

Для каждого режима используется своя папка. При повторе раннер использует
готовые эпизоды с теми же настройками. Скрипт сравнивает траектории по общим
сидам, проверяет совпадение стартов, целей и стен по хешу геометрии и считает
парные 95%-е бутстреп-интервалы. Время долёта сравнивается по парам эпизодов
с долетевшими дронами в обоих режимах. `brake_tick_rate` показывает долю
времени ожидания по всем дронам, `priority_releases` число повышений
приоритета за эпизод. Для быстрого прогона добавьте
`--layouts straight_open narrow_open elbow_open open_room --agents 8 --episodes8 2`.

### Пилот на исходном чекпоинте

На 8 дронах использованы сиды 0 и 1 для каждой из четырёх схем.
На 100 дронах проведена проверка открытой комнаты на сиде 0. Три числа
в ячейке идут в порядке `off / mask / brake`. Время усреднено среди долетевших
дронов в каждом эпизоде.

| Дроны | Схема | Долетели без контактов, % | Столкнулись с другим дроном, % | Время долёта, с |
| ---: | --- | --- | --- | --- |
| 8 | Прямой проход | 87,50 / 56,25 / 100 | 12,50 / 43,75 / 0 | 5,76 / 6,52 / 5,69 |
| 8 | Узкий проход | 100 / 81,25 / 100 | 0 / 18,75 / 0 | 6,15 / 6,54 / 6,30 |
| 8 | Г-образный проход | 12,50 / 12,50 / 12,50 | 43,75 / 43,75 / 0 | 11,02 / 11,38 / 10,96 |
| 8 | Открытая комната | 100 / 100 / 100 | 0 / 0 / 0 | 5,13 / 5,12 / 5,16 |
| 100 | Открытая комната | 63 / 68 / 92 | 37 / 32 / 8 | 5,91 / 5,80 / 6,06 |

В открытой комнате на 100 дронах доля чистых долётов выросла на 29 п.п.
относительно `off`. Столкновения между дронами снизились на 29 п.п., а среднее
время долёта выросло на 0,15 с. Рой проводил в ожидании 4,37% времени в
пересчёте на дрон. Временные повышения приоритета в пилоте не срабатывали.
Один сид на 100 дронах даёт проверку сценария и масштаба.

В Г-образном проходе на 8 дронах доля застрявших осталась 31,25% в `off` и `brake`.
Параметры с более ранним торможением (`brake-long`, горизонт 0,9 с и порог
2,3 порога столкновения) дали 68,75% чистых долётов в узком проходе при 100%
с базовыми параметрами. Базовые настройки сохранены.

[Данные всех 35 эпизодов](experiments/swarm100-1b/static_brake_pilot.csv).
Хеши стартов, целей и препятствий совпали во всех парных прогонах.
